# AI Usage and Authorship

AI assistance was used throughout this repository. The repository owner
reviewed all of it.

## Where AI assistance was used

- investigation write-ups, tickets, findings, timelines and incident reports;
- runbooks, governance documents and TryHackMe study notes;
- KQL queries and Sigma detection rules;
- Python and Bash scripts, tests and GitHub Actions workflows;
- analysis and reasoning during triage, severity assessment and escalation
  decisions;
- repository structure and the README.

## Human review

The repository owner reviewed every AI-assisted file and decision before
publication. Review covered technical correctness, consistency with the
retained evidence, the boundary between real, controlled-lab and synthetic
evidence, and the removal of sensitive data.

## What AI output is not

AI output is not evidence. Each case states its own evidence source and
provenance, and conclusions are limited to that evidence. Platform-generated
evidence (for example Microsoft Defender XDR and Microsoft Sentinel results,
PCAPs and log exports) is kept distinct from analyst-authored documentation,
as each case already records.

## Commit history

Most commits do not mark AI assistance individually. This file covers the
whole repository, including commits made before AI co-authorship was recorded
in commit messages.

## Integrity rule

AI assistance can accelerate drafting, analysis and review, but it does not
establish personal technical competence by itself.

Any CV, LinkedIn or interview claim based on this repository is limited to
work the repository owner can personally reproduce, explain, defend and
modify. See [INTERVIEW_DEFENSE.md](INTERVIEW_DEFENSE.md).
