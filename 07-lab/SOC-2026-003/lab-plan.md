# SOC-2026-003 — Production-Style Windows Endpoint Investigation

## Objective

Build and investigate a controlled Windows endpoint security incident using real
endpoint-generated telemetry and a documented Tier 1 SOC workflow.

This is a production-style laboratory investigation. It is not presented as a
real enterprise production incident.

## Host Environment

- Host: Apple Silicon Mac
- Architecture: ARM64
- CPU: Apple M2, 8 cores
- RAM: 8 GB
- Hypervisor: UTM
- Guest target: Windows 11 ARM64
- Repository: soc-analyst-lab
- Case: SOC-2026-003

## Resource Constraint

Because the host has 8 GB RAM, heavyweight services must not run concurrently
unless resource usage has been verified.

Planned operating model:

1. Windows endpoint active for telemetry generation and collection.
2. Heavy Docker/SIEM services stopped when they are not required.
3. Evidence exported and preserved.
4. Analysis services started separately where necessary.

## Planned Telemetry

The Windows endpoint should provide, where technically available:

- Windows Security Event Log
- Sysmon
- PowerShell Operational logging
- PowerShell Script Block Logging
- Process creation
- Parent/child process relationships
- Command-line telemetry
- Authentication events
- Persistence-related events
- Network connection telemetry
- User and host context

## Investigation Workflow

Alert
→ Validation
→ Context
→ Evidence
→ Timeline
→ Hypothesis
→ Correlation
→ MITRE ATT&CK mapping
→ Disposition
→ Severity
→ Close or Escalate

## Controlled Activity Principle

The investigation must be based on telemetry generated by actual controlled
actions executed inside the lab.

The investigation report must not manufacture telemetry to fit a predefined
incident narrative.

Benign and suspicious-looking activity should coexist where practical so that
the analyst must distinguish relevant evidence from noise.

## Target Scenario

A controlled Windows endpoint sequence may include:

- repeated authentication failures
- subsequent successful authentication
- PowerShell execution
- suspicious process ancestry
- persistence attempt
- controlled outbound network activity

No real malware is required.

Exact findings and ATT&CK techniques must be derived from collected evidence,
not declared as proven in advance.

## Evidence Requirements

Evidence must include, where applicable:

- raw exported event data
- timestamps
- hostname
- username
- process image
- parent process
- command line
- hashes
- source/destination network information
- event/provider identifiers
- evidence provenance
- SHA-256 integrity hashes

Synthetic evidence must not be represented as real endpoint telemetry.

## Detection Engineering Requirements

The completed case must contain:

- at least one detection rule
- reproducible detection logic
- positive test
- benign/negative test
- documented false-positive considerations
- documented tuning considerations
- automated regression test where technically practical

Sigma should be used for portable Windows detection logic where appropriate.

KQL may be included when the underlying schema and execution environment make
the query technically valid. A query must not be described as executed in
Microsoft Sentinel unless it was actually executed there.

## Tier 1 Investigation Requirements

The final investigation must document:

- alert or detection source
- initial triage
- affected host/user
- evidence reviewed
- event timeline
- observed behavior
- competing hypotheses where relevant
- contextual gaps
- disposition
- severity rationale
- escalation decision
- recommended next actions
- limitations

## MITRE ATT&CK Rule

ATT&CK mappings must be supported by observed evidence.

Candidate techniques may be documented during investigation, but must not be
presented as confirmed solely because the lab scenario was designed around
them.

## Completion Standard — 10/10 Within Defined Lab Scope

SOC-2026-003 reaches the defined completion standard only when all ten controls
below are satisfied:

1. Real Windows endpoint-generated telemetry.
2. Multiple relevant Windows telemetry sources.
3. Controlled actions generating observable security events.
4. Investigation performed from collected telemetry.
5. Evidence-based timeline and event correlation.
6. Detection authored and tested.
7. Benign/negative validation and tuning evidence.
8. Evidence-based ATT&CK mapping.
9. Tier 1 disposition, severity and escalation documentation.
10. Reproducibility, evidence integrity and Git/CI validation.

This score refers only to the defined production-style laboratory scope.

It does not claim equivalence to an enterprise SOC operating thousands of
endpoints, commercial EDR/XDR infrastructure, corporate identity systems,
ticketing systems, enterprise RBAC, 24x7 operations or real incidents.
