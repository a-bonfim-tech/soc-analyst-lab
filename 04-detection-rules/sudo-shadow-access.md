# Sudo Access to /etc/shadow

## Status

Experimental

## Detection Objective

Detect command execution through sudo where the requested target user is
root and the command accesses `/etc/shadow`.

The detection is intended to identify privileged access to a sensitive
credential file that may warrant investigation.

A match does not by itself establish malicious activity.

## Detection Hypothesis

A Linux sudo event containing all of the following characteristics should
match:

- the event is generated by sudo;
- the requested target user is root;
- the event records command execution;
- the command references `/etc/shadow`.

Conceptually:

    sudo event
    AND target user = root
    AND command is present
    AND command references /etc/shadow

## Scope

This initial implementation is based on synthetic Linux log fixtures created
for the SOC-2026-001 detection-engineering exercise.

It does not claim that the synthetic log format is the exact format of the
original incident telemetry.

The detection does not depend on:

- a specific hostname;
- a specific source IP address;
- a specific username;
- the `cat` executable;
- the SOC-2026-001 incident identifiers.

These values are intentionally excluded so that the behavioral hypothesis is
not unnecessarily tied to one incident.

## Test Cases

### Positive

`07-lab/detection-tests/SOC-2026-001/positive.log`

Expected result: match.

The fixture contains a synthetic sudo command event requesting root execution
and referencing `/etc/shadow`.

### Negative

`07-lab/detection-tests/SOC-2026-001/negative.log`

Expected result: no match.

The fixture contains legitimate-looking SSH and sudo administrative activity
but does not contain sensitive credential-file access.

## Current Prototype Logic

The current prototype requires the same event to contain all four indicators:

    sudo[
    USER=root
    COMMAND=
    /etc/shadow

This is test logic, not a production SIEM rule.

## Known Limitations

- The fixtures are synthetic.
- Only one positive and one negative scenario are currently tested.
- Text matching depends on the assumed log representation.
- Alternate sudo log formats may not match.
- Alternate representations of the target command may not match.
- Legitimate administrative access to `/etc/shadow` can produce a match.
- No production telemetry schema or SIEM field mapping has been established.
- No claim is made that a match represents compromise.

## Related Investigation

SOC-2026-001 documented privileged execution and access to `/etc/shadow`
following SSH authentication activity.

The investigation classified the activity as suspicious with authorization
pending and did not establish confirmed compromise.

## Controlled Lab Validation

The detection hypothesis was additionally validated against real telemetry
generated in an isolated Ubuntu 24.04 Docker laboratory.

The controlled reproduction generated failed SSH authentications, successful
SSH authentication, sudo execution, and access to `/etc/shadow`.

Evidence:

`10-evidence/SOC-2026-001/real-lab-auth.txt`

A Sigma implementation is available at:

`04-detection-rules/sigma/linux-sudo-shadow-access.yml`

The Sigma rule is syntax-parsed with pySigma and regression-tested against
positive and negative evidence in the repository.
