# Security and sensitive-data reporting

This repository contains educational lab artifacts, not a supported production security product. Detection examples have explicit coverage and validation limits; do not deploy them as a guarantee of protection.

Do not put secrets, private telemetry, training answers or exploit-bearing sensitive material into public issues, pull requests or comments. If GitHub displays **Report a vulnerability** under the repository Security tab, use that private channel. Its availability depends on live repository settings; this file alone does not enable it.

If private reporting is unavailable, open only a minimal public request for a secure reporting channel, without the sensitive details, and wait for the maintainer to provide one. No private email address or response-time commitment is asserted here.

Reports should identify the affected revision/path, concise impact, reproducible non-sensitive evidence and relevant limitations. Suspected credential exposure should halt publication while validity, revocation and historical scope are assessed. Do not test against third-party or production systems.
